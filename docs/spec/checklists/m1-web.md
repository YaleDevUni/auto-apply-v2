# M1 웹 콘솔 수동 확인 체크리스트

자동 게이트는 `make check` 안의 `web-check`(`npm run build`·`lint`·`test`, npm 이 없으면 경고 후 건너뜀). 아래는 사람이 브라우저로 확인하는 항목이다.

## 준비

1. 빈 데이터 디렉터리로 API 기동: `DATA_DIR=<임시폴더>/data AUTO_APPLY_CONFIG_DIR=<임시폴더>/cfg uv run auto-apply --port 8000`
   (`make api` 도 8000 이다. 개발 모드라 CORS 가 `http://localhost:5173` 을 연다 — §A10)
2. 웹: `make web` → `http://localhost:5173` 을 연다.

## 레이아웃 · 라우팅 (T1.4)

- [ ] 빈 DB 에서 `/` 로 들어가면 `/onboarding`(이력서로 시작하기)으로, 인적사항을 저장한 뒤에는 `/profile` 로 이동한다 (T1.5).
- [ ] 왼쪽 내비에 이력서로 시작·프로필·경험·답변·문서 5개가 있고, 현재 화면 항목이 강조된다.
- [ ] 없는 주소(`/nope`)는 "없는 화면입니다" 가 레이아웃 안에 뜬다.
- [ ] 브라우저 뒤로/앞으로 가기가 화면을 따라간다.

## 인적사항 화면 (T1.4)

- [ ] 빈 DB 에서 `/profile` 첫 진입: 에러 없이 빈 양식이 뜨고 저장 버튼은 비활성이다(`GET /api/profile` 404 = 아직 없음).
      양식 위에 "이력서로 시작하기" 링크 안내가 있다 (T1.5).
- [ ] 기본 항목(이름·연락처·이메일·링크·학력·스킬·언어)은 펼쳐져 있다. 링크·학력·언어는 "추가"로 행을 늘리고 휴지통으로 지운다.
- [ ] **추가 정보** 섹션은 기본으로 **접혀** 있고, 머리에 채운 개수(`n/6`)가 보인다.
- [ ] 펼치면 "비워두면 지원 중에 물어봅니다" 안내가 가장 위에 있다.
- [ ] 병역 사항·보훈·장애의 기본 선택지는 "비워두기 (지원 중에 질문)" 이다. 병역 사항을 고르면 군별·계급·복무 기간·비고 칸이 나타난다.
- [ ] 이름을 지우고 저장하면 저장되지 않고 이름 칸에 "이름을 입력하세요" 가 뜬다.
- [ ] 값을 바꾸면 저장 버튼이 켜지고, 저장하면 "저장했습니다" 토스트 후 다시 비활성이 된다. 새로고침해도 값이 남아 있다.
- [ ] 추가 정보의 빈 칸은 `null` 로 저장된다: 저장 후 `curl http://127.0.0.1:8000/api/profile` 에서 비운 항목이 `null`
      (보훈 "비대상" 은 `false`, 병역 "해당 없음" 은 `{"status": "not_applicable", ...}`).
- [ ] 스킬 `Python, React, Python` → 저장 후 `["Python", "React"]` (중복 제거).
- [ ] **주민등록번호 거부**(절대 규칙 5): 아무 칸에 `900101-1234567` 을 넣고 저장 → 빨간 토스트 "주민등록번호 형식의 값은 저장할 수
      없습니다" 가 뜨고 `GET /api/profile` 에 그 값이 없다. 응답·콘솔 어디에도 번호가 되돌아오지 않는다(개발자 도구 Network).
- [ ] 저장하지 않은 변경이 있을 때 다른 메뉴를 누르면 확인 창이 뜨고, 취소하면 화면에 남는다. 탭 닫기·새로고침도 브라우저 경고가 뜬다.
- [ ] 긴 양식을 아래로 스크롤해도 제목줄의 저장 버튼이 보인다.

## 로컬 보안 연동 (§A10, T1.4)

- [ ] 개발자 도구 Network 에서 `PUT /api/profile` 요청에 `X-Auto-Apply-Token` 헤더가 붙어 있고, `GET` 요청에는 없다.
- [ ] 페이지를 연 채로 API 를 **다른** `DATA_DIR` 로 재기동(토큰이 바뀜)한 뒤 저장 → 한 번 403(`invalid_token`) 후
      토큰을 다시 받아 저장이 성공한다.
- [ ] API 를 끈 상태로 새로고침 → "서버에 연결할 수 없습니다" 와 다시 시도 버튼. API 를 켜고 다시 시도하면 양식이 뜬다.

## 온보딩 — 이력서 파일 → 초안 검토 → 확정 (T1.5)

추출은 실제 LLM 이 필요하다(`LLM_PROVIDER=claude_cli` + 로그인된 `claude`). `stub` 이면 업로드가 "AI 응답을 해석하지 못했습니다" 로 끝난다.
픽스처: `tests/fixtures/resumes/dev_resume.pdf`·`nondev_resume.pdf` (가상 인물).

- [ ] `/onboarding` 에 안내 3줄(초안 생성 · 확정해야 반영 · 문서함에 저장 안 함/주민번호 가림)과 "이력서 파일 올리기" 버튼이 있다. 파일 창은 PDF·DOCX 만 보인다.
- [ ] 파일을 고르면 버튼이 "읽는 중…" 으로 바뀌고, 끝나면 `/onboarding/<draft_id>` 검토 화면으로 간다. `GET /api/documents` 에 그 파일이 **없다**.
- [ ] 검토 화면: 값이 있는 인적사항 항목과 모든 경험이 "채택" 으로 켜져 있고, 빈 항목은 "버림" 으로 흐리게 보인다.
- [ ] 경험의 "수정" 을 누르면 편집기가 펼쳐진다. 경험 이름을 비우고 "확정" → 확정되지 않고 "고칠 곳이 있습니다" + 이름 칸 에러.
- [ ] 서술 하나를 고치고, 연락처와 경험 하나를 끈 뒤 "확정" → "인적사항 n개 항목과 경험 m개를 반영했습니다" 토스트 후 `/profile` 로 이동.
      `GET /api/experiences` 에 켠 경험만 있고 고친 서술이 반영됐다. 끈 연락처는 기존 값 그대로다.
- [ ] 이미 인적사항이 있을 때 초안의 이름을 비워도 확정되고 기존 이름이 남는다. 인적사항이 없는데 이름을 끄고 다른 인적사항을 켜면
      "이름이 없습니다" 에러로 막힌다.
- [ ] 검토 중 값을 고치고 다른 메뉴 → 확인 창. "검토 내용 저장" 후 새로고침해도 고친 값이 남고, `/onboarding` 의
      "검토 중인 초안" 에 그 초안이 있다("이어서 검토").
- [ ] "초안 버리기" → 확인 후 `/onboarding` 으로 돌아가고 목록에서 사라진다.
- [ ] **주민번호 가림**(절대 규칙 5): 본문에 `900101-1234567` 이 든 DOCX/PDF 이력서를 올리면 검토 화면 위에
      "주민등록번호 형식의 값 1개를 가렸습니다" 가 뜬다. 초안(`GET /api/profile/drafts/<id>`)·서버 로그·데이터 디렉터리 어디에도 번호가 없다.
- [ ] 파일 이름에 주민번호 꼴이 있으면 "파일 이름에 주민등록번호 형식의 값이 있습니다" 토스트, 초안이 생기지 않는다.
- [ ] `claude` 로그아웃 상태면 "Claude 로그인이 필요합니다" 토스트(모델 응답 원문이 화면에 나오지 않는다).

## 경험 (T1.5)

- [ ] 경험이 종류별(회사·프로젝트·활동·교육)로 묶여 개수와 함께 보이고, 카드에 역할·기간·서술/첨부 개수·서술 목록이 있다.
- [ ] "경험 추가" → 이름 없이 저장하면 "이름을 입력하세요". 하위 프로젝트에 서술만 쓰고 제목을 비우면 "프로젝트 이름을 입력하세요".
- [ ] 저장된 경험을 다시 저장해도 `GET /api/experiences` 의 fact id·섹션 key 가 바뀌지 않는다(이력서 근거 유지).
      새 하위 프로젝트는 겹치지 않는 key(`s1`…)를 받는다.
- [ ] 첨부 문서 체크 → 저장 → 카드에 "첨부 1개". 문서 화면에서 그 문서를 지우면 경험 카드가 "첨부 0개" 가 된다.
- [ ] 편집 중 다른 메뉴 → 확인 창, 취소하면 편집이 남는다.
- [ ] 대표 링크가 `javascript:` 등 http(s) 가 아니면 링크가 아닌 글자로만 보인다.

## 답변 (T1.5)

- [ ] "답변 추가" → `희망 연봉은?*` 저장 → 목록에 `희망 연봉은` 으로 보인다(정규화). 갱신 시각이 보인다.
- [ ] 같은 질문(`희망  연봉은`)을 다시 추가 → "같은 질문의 답변이 이미 있습니다" 토스트(409), 목록은 1건.
- [ ] 답변에 `900101-1234567` → "주민등록번호 형식의 값은 저장할 수 없습니다", 저장되지 않는다.
- [ ] 수정·삭제(확인 창)가 된다. 검색 칸이 질문·답변 둘 다에서 찾는다.

## 문서 (T1.5)

- [ ] 규칙 안내 3줄(형식·10MB, 본문 주민번호 거부, 이미지·스캔본은 검사 못 함)이 있다.
- [ ] PDF 를 올리면 목록에 파일명·형식·크기·시각이 보이고, 파일명을 누르면 새 탭에서 열린다.
- [ ] 본문에 주민번호가 있는 PDF/DOCX → "문서 본문에 주민등록번호 형식의 값이 있어 올리지 않았습니다…" 전용 토스트(422), 목록에 없다.
- [ ] 확장자만 `.pdf` 인 텍스트 파일 → "PDF·DOCX·PNG·JPG 파일만…" 토스트(415).
- [ ] 삭제 확인 창에 "이 문서를 첨부한 경험에서도 빠집니다" 가 있다.
