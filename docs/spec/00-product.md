## 한 줄 요약

**직군 상관없이 누구나 자기 PC 에 설치해서, 원하는 채용 링크를 던지면 Claude 가 브라우저로
지원서를 끝까지 채워두고, 사람이 승인해야만 제출하는 도구.**

## 사용자 플로우

```
① 온보딩        웹에서 인적사항·학력·경력·경험·포트폴리오(선택) 입력
                (기존 이력서 PDF/DOCX 를 올리면 초안 자동 추출 → 사용자가 검토)
② 트리거        채용 링크를 올린다 (공고 URL 그대로, 또는 회사 채용 페이지 + "백엔드 신입 공고" 같은 자연어)
③ 이동·로그인   에이전트가 공고까지 이동. 로그인 벽을 만나면 멈추고 사람에게 넘김
                → 사람이 전용 크롬 창에서 직접 로그인 → "계속" → 이후 세션 재사용
④ 채우기        에이전트가 폼 작성·파일 업로드·자소서 문항 답변 초안 작성
                프로필에 없는 필수 항목은 중간에 질문 → 답은 프로필(답변 KB)에 저장돼 다음부터 자동
⑤ 제출 차단     하네스가 최종 제출을 코드 레벨에서 막는다. 에이전트는 "검토 준비됨"까지만 간다
⑥ 승인 큐       사용자가 스크린샷·입력값·생성 문서를 보고 승인 / 수정요청 / 거절
⑦ 제출          승인 → 에이전트가 세션으로 재진입해 기록된 값으로 다시 채우고, 값 대조 후 하네스가 제출
⑧ 수정요청      피드백 → 해당 지원 건으로 재진입해 고친 뒤 다시 ⑥
⑨ 학습          모든 실행의 실수·수정요청·사람 개입에서 교훈을 뽑아 자연어 가이드(사이트별+전역)에 자동 누적
```

## 절대 규칙 (v3)

1. **에이전트는 최종 제출을 할 수 없다.** 제출은 사람 승인 뒤 **하네스 코드**가 기록된 제출 대상에 대해서만 수행한다.
   가이드·프롬프트·LLM 출력 어떤 것도 하네스를 풀 수 없다.
2. **안전 모드 기본값.** 설정 `submit_mode=dry_run` 이 기본. `live` 전환은 사용자가 UI 에서 명시 확인해야 한다.
3. **CAPTCHA·SMS·본인인증 우회/자동해결 금지.** 계정 대리 생성 금지. 자격증명(비밀번호)을 앱이 저장·타이핑하지 않는다.
4. **없는 사실을 쓰지 않는다.** 이력서·자소서 생성물은 `ground_check` 로 프로필 근거에 묶인다.
5. **고유식별정보(주민등록번호 등)는 저장하지 않는다.** 필요하면 매번 ask_user, 답변 KB 에도 남기지 않는다.
6. **지원 상태 전이는 단일 통로**(`ApplicationService.transition`, 도메인 상태기계 검증)로만.

## 놓치기 쉬운 요구사항 (인터뷰 후 스펙에 추가한 것)

- **로그인 벽 감지 → 사람 핸드오프 → 재개.** 세션 만료도 같은 경로.
- **중복 지원 방지**: 같은 공고(정규화 URL)에 이미 SUBMITTED 가 있으면 트리거 시 경고.
- **증거 보관**: 페이지별 스크린샷 + 제출 후 확인 화면 스크린샷을 지원 건에 첨부.
- **로컬 보안**: 127.0.0.1 만 바인딩, `Origin` 검사 + 설치별 토큰 헤더 (악성 웹페이지의 localhost CSRF 방지).
- **PDF 렌더러를 Chrome print-to-PDF 로 교체** — WeasyPrint 는 Windows 에서 GTK 설치가 필요해 D2 와 충돌.
- **실행 비용/시간 표시**: 실행(run)마다 토큰·소요시간 기록 (API 키 경로에서 과금 가시성).
- **동시 실행 1건**: 전용 프로필 하나를 공유하므로 브라우저 실행은 직렬 큐. 문서 생성 같은 비브라우저 작업은 병렬 가능.
- **첫 실행 마법사**: Chrome 탐지, claude CLI 로그인/API 키 확인, 샘플 프로필.
